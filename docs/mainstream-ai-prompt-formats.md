# 2026年主流 AI 提示词（Prompt）格式与模板指南

在 AI 提示词工程（Prompt Engineering）中，结构化的提示词格式能够显著提升大语言模型（LLM）的输出稳定性、准确度和可控性。本文整理了当前最主流的四大提示词框架、XML 标签结构以及实用的设计原则。

---

## 一、 核心黄金法则框架：RTF 框架

### 1. 适用场景
日常 80% 的高频、快速开发任务。它是最轻量、编写最快的框架，能迅速限定 AI 的输出形态。

### 2. 结构构成
* **R (Role - 角色)**：告知 AI 扮演什么角色或拥有什么专业背景。
* **T (Task - 任务)**：明确具体、清晰的任务指令。
* **F (Format - 格式)**：指定输出的具体形状（如列表、表格、Markdown、JSON、代码等）。

### 3. 示例模板
```text
Role: 你是一位资深金融分析师。
Task: 阅读以下公司财报，并总结出三个最核心的潜在风险点。
Format: 请以 Markdown 的无序列表形式输出，按风险严重性从高到低排列。
```

## 二、 高情商/高精度框架：CO-STAR 框架

### 1. 适用场景
高要求、注重语气、情感和受众的文案撰写（如营销材料、社交媒体推文、公关邮件等）。

### 2. 结构构成
* **C (Context - 上下文/背景)**：提供该任务的背景信息或当前面临的情况。
* **O (Objective - 目标)**：期望 AI 达成的最终目的。
* **S (Style - 风格)**：定义写作风格（例如：极简主义、华丽、硅谷 VC 风）。
* **T (Tone - 语气)**：设置文章的情感色彩（例如：幽默、专业、安抚性、富有激情）。
* **A (Audience - 受众)**：明确谁会读到这段内容，以便 AI 调整用词深浅。
* **R (Response - 输出格式)**：限定最终输出的格式。

### 3. 示例模板
```text
Context: 我们即将为一款面向大学生的新型番茄工作法 App 举行线上发布会。
Objective: 撰写一封吸引他们报名的社群推文。
Style: 模仿科技博主的极简主义风格，多用动词。
Tone: 热情、充满活力且接地气。
Audience: 感到焦虑、时间碎片化的 18-22 岁在校大学生。
Response: 1 条不超过 200 字的小红书文案，配合恰当的 Emoji。
```

## 三、 探索与多方案框架：CRISPE 框架

### 1. 适用场景
头脑风暴与深度探索。当你需要 AI 给出多个不同的设计、方案或思路，并对它们进行横向对比和挑选时。

### 2. 结构构成
* **C (Capacity/Role - 角色能力)**：大模型的能力定位与专业广度。
* **I (Insight - 背景透视/洞察)**：提供关于目标任务的深度背景。
* **S (Statement - 任务陈述)**：明确陈述要做什么。
* **P (Personality - 个性特征)**：大模型应该展现的语气、偏好或态度。
* **E (Experiment - 实验与多重方案)**：要求模型提供 2~3 个备选方案或不同的侧重点。

### 3. 示例模板
```text
Capacity: 担任具有 10 年经验的产品设计专家。
Insight: 我们发现 40 岁以上的用户在首次登录医疗健康类 App 时流失率高达 45%。
Statement: 重新设计首次登录的用户引导流程（Onboarding Flow）。
Personality: 耐心、极度注重无障碍体验和细节。
Experiment: 请给出两种不同的方案：
            方案一：极简无干扰的单步卡片流；
            方案二：交互式的智能引导对话流。
```

## 四、 严谨质量对齐框架：RICE 框架

### 1. 适用场景
输出质量高度依赖于特定风格、特定格式，或需要遵循既有模板（例如学术论文润色、标准化技术文档编写）。

### 2. 结构构成
* **R (Role - 角色)**：AI 的专家角色定义。
* **I (Instructions - 步骤指示)**：分步执行的清晰逻辑（1, 2, 3）。
* **C (Context - 背景/约束)**：相关背景与硬性约束。
* **E (Examples - 示例/Few-Shot)**：给 AI 喂 1~2 个高质量的样本，让其进行少样本（Few-Shot）学习。

### 3. 示例模板
```text
Role: 资深软件技术文档工程师。
Context: 我们正在重构 API 接口说明，需要符合标准的 OpenAPI 文档风格。
Instructions: 
  1. 读取以下接口原始代码。
  2. 提取参数及返回值。
  3. 按照 Examples 中的格式重新排版。
Examples: 
  [这里放入你满意的历史技术文档样例]
```

## 五、 结构化标签格式：XML 标签格式（Claude 及长文本模型首选）

### 1. 适用场景
当提示词非常复杂，包含多处代码、参考文档、长文本、变量或包含复杂的判断逻辑时。大语言模型（尤其是 **Claude** 系列）对 XML 标签有着天然的敏感度和结构解析能力。

### 2. 结构构成
使用自定义的类似 HTML 的成对标签（如 `<context>`、`<rules>`、`<example>`、`<input_data>`）将提示词的不同维度物理隔离，防止模型混淆指令和数据。

### 3. 示例模板
```xml
<system_role>
你是一名资深的技术代码审查员。
</system_role>

<instructions>
请检查 <source_code> 标签内的代码是否存在明显的内存泄露、并发竞态或未捕获的空指针异常。
</instructions>

<rules>
- 必须在发现问题处指出具体行号。
- 严禁指出语法层面的琐碎拼写问题。
- 若无上述三类硬伤，直接回复"PASS"。
</rules>

<source_code>
// 放入具体的代码片段
</source_code>
```

## 六、 提示词工程的普适原则与趋势

1. **五大核心要素不可少**：任何提示词框架的核心最终都可以简化为：**角色 (Persona) + 任务 (Task) + 背景 (Context) + 示例 (Examples) + 约束 (Constraints)**。
2. **“少样本（Few-Shot）”依旧是最强杀手锏**：在框架中引入 `Examples`，模型的理解和拟合度将呈指数级提升。
3. **物理隔离（XML 标签）防止指令遗忘**：利用 XML 标签、Markdown 的 H2/H3 标题或 JSON 结构来书写提示词，能有效防止 AI 出现“指令遗忘（Instruction Drift）”问题。
