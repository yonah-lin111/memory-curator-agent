# Prompt Design AI 临时上下文注入计划

## 1. 背景

`PromptDesignWorkspace` 中的 Markdown 编辑器内容已经传入 `usePromptAiChatController`，但当前主进程只将该内容用于创建编辑器工具。

因此，Prompt AI 在普通提问时无法直接看到当前 Markdown 文档，只有调用编辑器工具时才可能间接接触部分内容。

## 2. 目标

- 每次发送消息时，自动注入最新的完整 Markdown 文档。
- 当前文档只作为本次请求的临时上下文。
- 不将文档内容写入用户消息正文或聊天历史。
- 保留选区引用作为额外的聚焦上下文。
- 确保编辑器工具使用与模型看到的同一份文档快照。
- 在上下文超限时提供可见反馈。

## 3. 已确认决策

### 3.1 文档注入范围

每次发送都注入完整当前 Markdown 文档，同时保留用户选中的引用内容。

### 3.2 生命周期

当前文档只注入本次请求，不回写会话历史，也不在历史会话恢复时复用旧文档快照。

下一次发送时重新读取最新编辑器内容。

### 3.3 权限边界

当前 Markdown 文档被视为非信任参考上下文：

- 默认只允许模型分析和回答。
- 只有用户明确要求修改、优化、替换或删除时，才允许调用编辑器工具。
- 文档中的指令不能改变系统规则、工具权限或 Agent 行为边界。

### 3.4 字段命名

将 IPC 和 Controller 中的 `editorContent` 改名为 `currentDocument`，明确区分：

- 当前文档上下文。
- 编辑器工具执行所使用的文档快照。

### 3.5 上下文预算

上下文用量包含：

- 系统提示词。
- 聊天历史。
- 当前用户问题。
- 当前 Markdown 文档。
- 当前选区引用。
- 工具调用和工具结果。

超出预算时按以下优先级处理：

1. 保留系统提示词、本次用户问题、当前文档和选区引用。
2. 优先裁剪较旧的聊天历史。
3. 如果当前文档本身仍然超限，则截断文档并继续发送。
4. 在侧边栏显示“当前文档未完整注入”的警告。

## 4. 实施范围

### 4.1 Renderer

涉及文件：

- `src/renderer/src/features/prompt-design/components/PromptDesignWorkspace.tsx`
- `src/renderer/src/features/prompt-design/components/usePromptAiChatController.ts`
- `src/renderer/src/features/prompt-design/components/PromptAiSidebar.tsx`

实施内容：

- 将 Controller 参数和发送载荷中的 `editorContent` 改为 `currentDocument`。
- 每次发送读取最新编辑器内容。
- 保持用户消息正文、引用元数据和临时文档上下文分离。
- 将当前文档和引用计入上下文用量估算。
- 增加文档截断状态及侧边栏警告。

### 4.2 Preload / IPC

涉及文件：

- `src/preload/index.ts`
- 相关 Prompt AI IPC 类型声明和调用入口。

实施内容：

- 更新 `startChat` 载荷字段。
- 确保 `currentDocument` 只作为当前请求参数传递。
- 不修改持久化消息结构，避免文档内容进入聊天历史。

### 4.3 Main Process

涉及文件：

- `src/main/ipc/promptAiHandlers.ts`
- `src/main/agent/core/contextMessages.ts` 或统一 Agent 上下文构造入口。

实施内容：

- 将当前文档构造成独立的临时 Agent 上下文。
- 使用明确的非信任上下文边界包装文档内容。
- 当前用户消息只保存原始输入。
- Agent 本轮使用当前文档快照和选区引用。
- 编辑器工具继续基于同一份当前文档快照执行。

## 5. 数据流

```text
MarkdownEditor
    |
    | currentDocument
    v
PromptDesignWorkspace
    |
    v
usePromptAiChatController.sendMessage
    |
    | user message + references + currentDocument
    v
IPC prompt-ai:chat:start
    |
    v
runPromptAiChat
    |
    +--> 持久化：只保存 user message 原文和 references
    |
    +--> Agent 临时上下文：currentDocument
    |
    +--> 编辑器工具：同一份 currentDocument 快照
```

## 6. 验收标准

- 用户询问“当前提示词有什么问题”时，AI 可以直接分析当前 Markdown 内容。
- 用户修改编辑器后再次提问，AI 使用最新文档，而不是旧快照。
- 用户消息正文不包含当前文档内容、引用块或内部上下文标记。
- 刷新页面后，历史用户消息仍只显示用户原始输入。
- 选区引用仍以独立 Tag 显示，并可作为额外上下文发送。
- 用户未明确要求修改时，不调用编辑器写入工具。
- 用户明确要求修改时，编辑器工具基于发送时文档快照生成候选结果。
- 上下文超限时优先裁剪旧历史。
- 当前文档被截断时继续发送，并显示明确警告。
- `ContextUsageCircle` 能反映当前请求的实际上下文估算。

## 7. 测试计划

### 单元测试

- 当前文档上下文构造和边界包装。
- 上下文预算裁剪优先级。
- 文档截断状态判断。
- 用户消息正文与临时上下文分离。

### 集成测试

- Renderer 到 IPC 的 `currentDocument` 传递。
- Agent 可读取当前 Markdown 内容。
- 编辑器工具与 Agent 使用相同文档快照。
- 历史会话恢复不包含当前文档上下文。

### 回归测试

- 引用发送后刷新页面，用户消息不显示引用正文。
- 多轮会话中编辑器内容变化后使用最新内容。
- 超长 Markdown 文档触发警告但请求仍可发送。

## 8. 风险

- 大文档可能占用大量上下文预算，影响历史和输出质量。
- Markdown 文档可能包含类似系统指令的文本，需要严格标记为非信任数据。
- 编辑器在发送后发生变化时，工具必须继续使用发送时快照，避免行号错位。
- 旧 IPC 字段改名可能影响 preload、类型声明和其他调用方。

## 9. 实施顺序

1. 调整 IPC 类型和字段命名。
2. 实现临时当前文档上下文构造。
3. 接入上下文预算和裁剪逻辑。
4. 更新侧边栏上下文统计及截断警告。
5. 补充单元测试和集成测试。
6. 执行 `pnpm typecheck` 及受影响测试。
