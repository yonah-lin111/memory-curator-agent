# 记忆策展 Agent 项目开发文档

## 1. 项目功能定位

记忆策展 Agent 是一个面向个人长期记录与回顾的记忆整理工具。它帮助用户把每天产生的计划、执行过程、自由笔记、日记内容、聊天素材与主观感受整理到同一套个人工作台中，并在周期回顾中提炼长期主题、变化轨迹与重要记忆线索。

项目不以“保存更多内容”为唯一目标，而是强调对个人素材的持续策展。系统需要让用户能够在日常使用中完成记录，在周度回顾中看见阶段性变化，在长期追踪中理解重复出现的模式、冲突和未完成议题。

## 2. 目标用户

### 2.1 稳定记录但缺少回顾的人

这类用户已经有记录计划、随记或日记的习惯，但记录内容往往分散在多个工具中，长期难以回看。系统需要帮助他们把日常素材按时间与主题组织起来，让记录不只停留在堆积层面。

### 2.2 需要统一管理个人输入的人

这类用户会同时产生 todo、笔记、日记、聊天片段、截图文字等不同类型输入。系统需要提供统一入口，把不同来源的文本材料整理到同一个日视图与记忆体系中。

### 2.3 需要提炼人生素材的人

这类用户可能是创作者、咨询者或深度思考者，他们关注记录背后的主题、情绪变化、行为模式与叙事线索。系统需要帮助他们从零散内容中提炼可命名、可追踪、可复盘的长期主题。

## 3. 核心使用节奏

项目采用“日输入 + 周整理 + 长期追踪”的核心使用节奏。

### 3.1 日输入

用户在每天的使用过程中持续输入计划、笔记、日记和其他文本素材。系统需要围绕单日组织内容，让用户清楚看到当天计划、已记录事项、主观感受和重要片段。

### 3.2 周整理

系统按周对每日输入进行整理，帮助用户回看一周内发生的事件、计划完成情况、感受变化、重复主题和关键记忆。周度整理不是简单汇总，而是需要形成可复盘的阶段性视图。

### 3.3 长期追踪

系统从连续记录中识别长期主题、行为模式、情绪波动和叙事变化。长期追踪需要支持主题命名、主题关联、变化对比和历史回看，让用户能够理解某些问题如何反复出现、发展或消退。

## 4. Agent 能力体现

### 4.1 输入理解能力

Agent 需要理解用户输入的内容类型，而不是只把输入当作普通文本保存。用户可能输入一句待办、几段聊天记录、一段日记、一条临时想法，或者一段从截图中识别出来的文字。Agent 需要判断这些内容更接近计划、事实记录、主观表达、外部素材还是可追踪线索。

输入理解能力体现在三个方面：识别内容来源、判断内容用途、建议内容归属。系统需要让用户在低负担输入的情况下，仍能得到有结构的记录结果。例如，用户粘贴一段聊天内容后，Agent 可以识别其中的关键事件、待办事项、情绪表达和可能进入长期追踪的主题。

### 4.2 日常整理能力

Agent 需要把同一天产生的 todo、笔记和日记组织到同一个日视图中。它不是简单按创建时间堆叠内容，而是帮助用户看清当天的计划、过程记录、主观感受和重要片段分别是什么。

日常整理能力体现在当天记录的结构化呈现。用户可以看到今天准备做什么、实际记录了什么、有哪些感受值得留意、哪些素材可能需要在周度回顾中继续整理。系统需要在日常层面形成清晰的记录秩序，让用户不需要等到很久以后才开始整理。

### 4.3 记录归类能力

Agent 需要区分 todo、自由笔记、日记、记忆片段和长期主题。不同记录类型承担不同功能：todo 面向执行，笔记面向素材，日记面向主观叙事，记忆片段面向重要节点，长期主题面向持续追踪。

记录归类能力的价值在于避免所有内容混入同一个笔记流。系统需要在保留用户原始表达的同时，帮助用户把内容放到更合适的位置，使后续回看、整理和追踪更清楚。

### 4.4 周度策展能力

Agent 需要按周整理用户的日常输入，从多个日期的记录中提炼阶段性回顾。周度策展不是把一周内容压缩成摘要，而是从计划执行、事实记录、主观感受、重复主题和关键事件中形成可复盘的结构。

周度策展能力体现在对一周脉络的提炼。系统需要帮助用户看到哪些事情完成了，哪些事项反复延后，哪些情绪频繁出现，哪些主题开始浮现，哪些记忆片段值得被保留。它的目标是让用户在一周结束时看到阶段性的变化，而不是只看到零散记录。

### 4.5 长期主题发现能力

Agent 需要从连续记录中发现长期主题。长期主题不是用户一次输入就能完全定义的内容，而是从多天、多周的记录中逐渐显现出来的反复关注点。

长期主题可以来自职业选择、创作方向、关系互动、生活习惯、情绪波动、决策模式或个人困惑。Agent 需要识别这些主题在不同记录中的重复出现，并将分散素材串联为可追踪的个人脉络。

### 4.6 变化追踪能力

Agent 需要帮助用户比较不同时期的记录变化。变化可能体现为计划执行方式的变化、关注主题的变化、情绪表达的变化、对同一问题理解方式的变化，或某个长期议题的推进与停滞。

变化追踪能力的重点是回答“现在和过去有什么不同”。系统需要让用户看到变化发生在哪些记录中、与哪些事件相关、是否形成了持续趋势。

### 4.7 记忆命名能力

Agent 需要帮助用户为重要记忆片段命名。命名不是给内容贴普通标签，而是把一个值得回看的事件、感受、选择或转折提炼成可识别的记忆节点。

记忆命名能力可以让用户在长期回看时快速定位关键内容。例如，一段关于职业选择的日记可能被命名为“第一次明确想转向独立创作”，一段反复出现的关系记录可能被命名为“在冲突中持续退让”。这些命名需要服务于理解和追踪，而不是制造标签堆积。

### 4.8 记忆关联能力

Agent 需要把分散的记录、片段和主题建立关联。关联可以发生在同一主题下，也可以发生在相似情绪、相似行为模式、同一人物关系、同一决策问题或同一长期目标之间。

记忆关联能力体现在帮助用户看见“这些内容为什么有关”。系统需要避免只做关键词匹配，而是围绕事件、主题、感受和变化关系建立更有意义的连接。

### 4.9 模式识别能力

Agent 需要识别用户记录中反复出现的行为模式、情绪波动和决策倾向。例如，某些任务总是在周末前被延后，某类关系对话总是伴随强烈消耗感，某个创作主题总是在一段时间后被重新提起。

模式识别能力的目标不是评价用户，而是帮助用户看见重复结构。系统需要把重复出现的内容整理为可理解的观察结果，并与具体记录保持连接。

### 4.10 冲突与未完成议题识别能力

Agent 需要识别用户叙事中的冲突、断裂和未完成议题。冲突可能体现为计划与行动不一致、表达愿望与实际选择不一致、不同时间对同一问题的态度变化，或某些问题被反复提起但没有推进。

这项能力需要保持克制。系统应帮助用户看见记录中的张力和未完成部分，但不做诊断式判断，也不替用户下结论。

## 5. 功能总览

### 5.1 多来源文本输入

系统支持用户直接输入文本，也支持粘贴聊天内容、整理外部文本材料，以及通过 LLM 对输入内容进行识别和归类。输入内容可以来自计划、随记、日记、聊天记录、截图提取文本或其他个人素材。

系统需要尽量降低记录门槛。用户不必在输入时完全确定内容类型，系统可以根据内容特征辅助识别，并将素材放入合适的记录位置。

### 5.2 每日 todo 计划

系统支持用户创建和查看每日 todo。todo 用于承载当天的计划和执行事项，是日视图中的执行层内容。

每日 todo 需要体现计划性与完成状态。用户应能够围绕当天目标查看待处理事项、已完成事项和可能延后的事项，从而理解一天的执行情况。

### 5.3 自由笔记

系统支持用户记录自由笔记。自由笔记用于承载临时想法、事实记录、观察、素材片段和未整理内容。

自由笔记不要求具备完整结构。它的重点是快速捕捉，并在后续整理中被纳入日记录、周度回顾或长期主题追踪。

### 5.4 日记记录

系统支持用户记录和查看日记条目。日记用于承载更主观、更完整的个人表达，包括感受、反思、当天总结、困惑和自我观察。

日记功能需要与 todo 和笔记区分。todo 偏向执行，笔记偏向素材，日记偏向主观叙事与意义表达。

### 5.5 当日计划视图

系统提供当日计划视图，用于集中展示当天 todo、笔记和日记相关内容。用户进入系统后，应能够快速理解今天已经计划了什么、记录了什么、还有哪些内容值得继续整理。

当日计划视图是日常使用的主要入口，需要支持用户围绕当天持续补充内容。

### 5.6 笔记列表

系统支持以列表形式查看笔记。笔记列表用于帮助用户回看已经记录的素材，快速定位某一天、某一类或某个主题相关的记录。

笔记列表不只是静态归档入口，也应服务于后续策展。用户需要能够从列表中发现可被整理、关联或提升为主题的素材。

### 5.7 日记条目查看

系统支持查看历史日记条目。用户可以按时间回看自己的主观记录，理解某一阶段的状态变化与叙事线索。

日记条目查看需要保留日记的完整表达，避免仅以摘要替代原始记录。

### 5.8 周度策展

系统支持对一周内的输入进行策展。周度策展需要围绕一周的计划执行、事实记录、主观感受、重要事件和反复出现的主题生成结构化回顾。

周度策展的目标是帮助用户从每天的碎片中看到阶段性脉络。它应突出变化、重复、冲突和重要记忆，而不是只罗列记录数量。

### 5.9 长期主题追踪

系统支持从历史输入中提炼长期主题，并持续追踪主题的变化。长期主题可以来自重复出现的计划、行为模式、情绪表达、关系议题、创作方向、职业选择或个人困惑。

长期主题需要具备可命名性和可追踪性。系统应帮助用户看到某个主题在不同时间如何出现、如何变化、与哪些记忆片段相关。

### 5.10 变化对比

系统支持对不同时期的记录进行变化对比。变化对比可以用于观察计划执行习惯、情绪状态、关注主题、决策倾向和叙事方式的变化。

变化对比的重点是展示趋势与差异，帮助用户理解“现在与过去有什么不同”。

### 5.11 记忆片段命名与关联

系统支持为重要记忆片段命名，并建立片段之间的关联。被命名的记忆片段可以成为长期主题的一部分，也可以作为用户之后回看的关键节点。

记忆片段不应只是孤立摘要。系统需要帮助用户识别它与时间、主题、感受、事件和其他片段之间的关系。

### 5.12 模式与冲突识别

系统需要从用户记录中识别重复出现的行为模式、情绪波动、决策倾向、叙事冲突和未完成议题。

模式识别关注“反复出现的东西”，冲突识别关注“前后不一致或尚未解决的东西”。这些能力用于支持长期自我理解，而不是对用户做简单评判。

## 6. 主要功能模块

### 6.1 输入管理模块

输入管理模块负责接收用户输入的文本、粘贴内容和 LLM 识别结果。它需要支持多种来源的个人素材，并帮助用户降低分类成本。

该模块的功能重点包括：接收文本输入、接收聊天内容粘贴、接收截图识别后的文字内容、辅助判断输入类型、将输入纳入日视图或后续策展流程。

### 6.2 日常记录模块

日常记录模块负责承载用户每天的 todo、自由笔记和日记。它是用户高频使用的核心模块。

该模块的功能重点包括：创建每日 todo、查看当日 todo、记录自由笔记、记录日记、查看当天内容、区分执行事项、素材记录和主观表达。

### 6.3 日视图模块

日视图模块负责按日期组织用户输入。它需要让用户围绕某一天理解自己的计划、记录和感受。

该模块的功能重点包括：展示当日计划、展示当日笔记、展示当日日记入口、呈现当天的重要输入、支持围绕当天继续补充内容。

### 6.4 回顾整理模块

回顾整理模块负责支持周期性回看，尤其是一周维度的整理。它需要把一周内的日输入组织为可阅读、可复盘的回顾结果。

该模块的功能重点包括：生成周度回顾、整理一周事件、呈现计划完成情况、提取感受变化、识别重复主题、标记关键记忆。

### 6.5 主题追踪模块

主题追踪模块负责识别并维护长期主题。它需要把用户分散在不同日期的记录连接起来，形成可持续追踪的个人脉络。

该模块的功能重点包括：提炼长期主题、命名主题、关联相关记忆片段、展示主题历史、对比主题变化、发现主题与行为或感受之间的关系。

### 6.6 记忆策展模块

记忆策展模块负责将普通记录提升为有意义的记忆线索。它关注内容之间的关系、主题背后的变化，以及值得被用户重新看见的片段。

该模块的功能重点包括：识别重要记忆片段、为片段命名、建立片段关联、发现叙事冲突、标记未完成议题、辅助形成长期回看线索。

## 7. 功能边界

### 7.1 当前功能范围

当前需要覆盖以下功能：

- 文本输入
- 聊天内容粘贴
- LLM 识别输入
- 截图内容理解与文本提取
- 每日 todo 计划
- 自由笔记
- 日记记录
- 当日计划视图
- 笔记列表
- 日记条目查看
- 周度策展
- 长期主题追踪
- 变化对比
- 重要记忆片段命名与关联

## 8. 功能非目标

### 8.1 不做通用团队协作工具

项目面向个人记录与个人回顾，不以多人任务分配、团队看板、权限协作或组织级知识库为核心目标。

### 8.2 不做纯归档型笔记系统

项目不只是保存笔记和提供搜索。它需要进一步帮助用户整理、命名、关联和追踪记忆线索。

### 8.3 不做单次摘要工具

项目不以一次性总结某段文本为主要价值。它强调长期连续输入后的周期回顾与主题沉淀。

### 8.4 不替代专业心理咨询

系统可以帮助用户观察感受、模式与冲突，但不应提供诊断结论，也不应替代专业心理咨询或医疗建议。

## 9. 功能验收关注点

### 9.1 日常记录是否顺畅

用户应能够快速输入 todo、笔记和日记，并在当天视图中清楚看到这些内容。

### 9.2 信息类型是否清晰

系统需要让用户理解 todo、笔记、日记、记忆片段和长期主题之间的区别，避免所有内容混在同一个列表中。

### 9.3 周度回顾是否有复盘价值

周度回顾应能够呈现一周内的重要事件、计划执行、感受变化和重复主题，而不是只做简单汇总。

### 9.4 长期主题是否可追踪

用户应能够看到长期主题如何从多个日期的记录中形成，并继续查看主题的历史变化。

### 9.5 记忆关联是否有意义

系统生成或维护的记忆关联应帮助用户理解内容之间的关系，而不是制造无意义的标签堆积。
