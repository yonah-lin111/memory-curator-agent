# Sidebar Navigation Layout Design

## 背景

项目正在根据 `docs/project-development.md` 继续完善记忆策展 Agent 的左侧导航栏。当前工作只覆盖静态页面结构和布局，不接入真实路由、页面切换、持久化状态或业务数据。

左侧导航栏需要体现项目核心节奏：日输入、周整理、长期追踪。它应帮助用户理解 `Today`、笔记、日记、周度策展、长期主题和记忆片段之间的关系，而不是把所有入口平铺成普通工具列表。

## 目标

- 将左侧导航从平铺入口改为按使用节奏分组的静态结构。
- 保持黑色主题、`#212121` 次级容器、`6px` 圆角和无渐变约束。
- 保留现有左侧折叠能力，折叠后仍可识别主要入口。
- 在移动端沿用当前纵向堆叠思路，避免小屏出现难用的固定窄侧栏。
- 用最小改动完成布局迭代，优先修改 `Sidebar.tsx` 与对应测试。

## 非目标

- 不接入 React Router 或任何真实页面切换。
- 不新增全局状态管理。
- 不新增业务数据模型、数据库表或 IPC 通信。
- 不实现导航项点击行为。
- 不重构中间工作区和右侧策展栏。

## 方案选择

采用“节奏分组型”布局。

该方案按产品使用节奏组织导航：`DAILY` 对应日输入，`LIBRARY` 对应历史素材回看，`CURATION` 对应周整理与长期追踪。它比当前平铺结构更贴合项目文档，也比时间轴优先型更均衡，不会削弱长期主题和记忆片段的产品层级。

## 信息架构

左侧导航栏由四个纵向区域组成。

### 品牌区

展示 `MEMORY CURATOR`、本地优先短文案和品牌图标。展开态显示完整文字，折叠态仅显示图标。

### 分组导航区

导航分为三组。

- `DAILY`：`Today`。描述为“计划 / 随记 / 日记”。静态标记为当前页。
- `LIBRARY`：`Notes`、`Journal`。分别对应自由笔记列表与日记条目查看。
- `CURATION`：`Weekly Review`、`Themes`、`Memories`。分别对应周度策展、长期主题追踪、记忆片段命名与关联。

`Settings` 不放入主流程分组，作为底部辅助入口。

### 周定位卡片

保留轻量周定位信息，放在主导航之后或底部状态之前。展开态显示 `2026 MAY · WEEK 22` 与一周日期；折叠态只显示当前日期或日期小点。

该区域保持静态展示，不做日期选择交互。

### 底部状态区

展示本地优先状态，例如 `Local Vault`、`Last saved: Today 21:45`、`Local-first storage`。它用于增强桌面应用的可信感，但视觉权重低于主导航。

## 布局

### 桌面展开态

侧栏宽度保持约 `256px`，使用当前三栏布局。内部结构按品牌区、分组导航区、周定位卡片、底部状态区排列。主导航项使用图标、标题、短描述的组合。

当前页 `Today` 使用白底黑字作为激活态；其他项使用低饱和白色文字。分组标题使用小字号、字距和低透明度区分层级。

### 桌面折叠态

侧栏宽度保持约 `64px`。折叠态隐藏品牌文字、分组标题、导航描述、状态文案和完整日期卡片，只保留品牌图标、导航图标、当前日期标识、状态图标和设置图标。

折叠按钮沿用当前圆形按钮，保持 `h-6 w-6 rounded-full`，不改变既有测试语义。

### 移动端

`lg` 以下继续使用纵向堆叠。侧栏作为顶部块状导航区域出现，不固定在左侧，也不强制折叠成窄栏。这样避免移动端信息过密，同时保留当前应用壳层的滚动策略。

## 组件边界

`App` 继续只负责三栏壳层组合与左右栏折叠状态。

`Sidebar` 负责左侧导航的静态数据、分组渲染、周定位展示、本地状态展示和折叠态布局。

不拆分新组件。当前改动规模较小，拆出 `NavigationGroup` 或 `StatusCard` 会增加文件与命名成本，暂时没有复用价值。

## 静态数据结构

`Sidebar.tsx` 内保留静态数组。主导航从单层 `NAVIGATION_ITEMS` 调整为分组数组，每组包含标题和导航项列表。

导航项字段包括 `id`、`label`、`description`、`icon`。如需展示短徽标，可在静态结构中添加 `meta` 字段，但首版不需要。

周日期数据继续使用稳定字段作为 `key`，避免使用数组下标。

## 交互与无障碍

当前只保留折叠按钮交互。导航项使用静态元素或禁用交互语义，不制造可以点击但无响应的假交互。

`Today` 保留 `aria-current="page"`。主导航保留 `aria-label="侧边栏主导航"`。折叠按钮的 `aria-label` 沿用“折叠左侧导航栏 / 展开左侧导航栏”。

折叠态图标需保持足够可见度。移动端和桌面端都不引入悬浮菜单，因为本阶段不实现真实导航行为。

## 样式约束

- 主背景为 `#000000`。
- 侧栏容器为 `#212121`。
- 圆角统一为 `6px`。
- 禁止使用渐变色。
- 动效只使用克制的透明度、颜色和宽度过渡。
- 不引入新的全局 CSS，除非现有 Tailwind 类无法表达必要状态。

## 测试与验收

更新现有 `App.test.tsx` 中与侧栏结构相关的断言。

需要覆盖：

- 默认展示 `MEMORY CURATOR`、`DAILY`、`LIBRARY`、`CURATION`。
- 默认展示 `Today` 且保留当前页语义。
- 折叠左侧导航栏后隐藏品牌文字和分组标题。
- 折叠按钮继续保持 `h-6 w-6 rounded-full`。
- 不破坏右侧策展栏折叠测试、待办弹窗测试和中间容器测试。

验证命令：

- `pnpm test`
- `pnpm typecheck`

## 风险与处理

主要风险是侧栏信息过多导致移动端顶部区域变长。处理方式是在移动端保留纵向布局，但控制分组间距和状态区权重，避免本地状态卡片抢占首屏。

另一个风险是折叠态图标缺少文字后辨识度下降。当前阶段不做真实悬浮提示，因为没有路由交互；通过图标顺序与当前页白色激活态降低风险。

## 交付范围

实现阶段只应修改以下文件：

- `src/renderer/src/components/Sidebar.tsx`
- `src/renderer/src/App.test.tsx`

如测试或类型检查暴露必要的样式问题，可以小范围修改 `src/renderer/src/styles.css`，但默认不需要。若执行流程创建项目本地 worktree，需要新增或调整 Vitest 配置以排除 `.worktrees/**`，避免根目录测试扫描隔离工作区副本。
